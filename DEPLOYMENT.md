## 1️⃣ Neon — Production Database

1. Create a **new Neon project** called `road-warrior-prod`.
2. Pick a region close to your backend host (e.g. `ap-southeast-1` for Singapore / India).
3. Copy the **asyncpg** connection string — save it as the production `DATABASE_URL`.
4. (Optional but recommended) Enable **branching** so you can create `staging` and `preview` branches.
5. Run migrations from your CI or one-off:
   ```bash
   DATABASE_URL="postgresql+asyncpg://...neondb?sslmode=require" \
     alembic upgrade head
   ```

### Backups
- Neon Pro plan includes 7-day PITR (point-in-time recovery).
- Free plan does not — schedule `pg_dump` to S3/Backblaze if you go to prod on free.

## 2️⃣ Backend — Fly.io (recommended) / Railway / Render

### Fly.io

```bash
# Install flyctl: https://fly.io/docs/hands-on/install-flyctl/
cd backend
fly launch --name road-warrior-api --region sin
fly secrets set DATABASE_URL="postgresql+asyncpg://..."
fly secrets set JWT_SECRET="$(openssl rand -hex 32)"
# ... set all other secrets
fly deploy
```

`backend/Dockerfile` is already configured for this. The `fly.toml` (not in repo) is auto-generated by `fly launch`.

### Railway

1. New project → "Deploy from GitHub repo" → pick this repo → set root to `backend/`.
2. Add a **Postgres** plugin (or skip and use Neon).
3. In **Variables**, paste all env vars from `backend/.env.example`.
4. Set **Start command**: `alembic upgrade head && uvicorn app.main:app --host 0.0.0.0 --port $PORT`

### Render

1. New → **Web Service** → connect GitHub repo → root = `backend`.
2. **Build command**: `pip install -r requirements.txt`
3. **Start command**: `alembic upgrade head && uvicorn app.main:app --host 0.0.0.0 --port $PORT`
4. Add all env vars from `backend/.env.example`.

### Health-check endpoint
Use `GET /api/health` as the platform's health-check URL.

## 3️⃣ Frontend — Vercel (recommended)

1. Go to https://vercel.com → **New Project** → import this repo.
2. **Root Directory**: `frontend`
3. **Framework Preset**: Next.js (auto-detected)
4. **Build command**: `npm run build` (default)
5. Add env vars (see [ENV.md](./ENV.md) — frontend section):
   ```
   NEXT_PUBLIC_API_URL=https://api.roadwarrior.app
   ```
6. Deploy. Vercel will give you `https://road-warrior.vercel.app`.

### Custom domain
- In Vercel → Settings → Domains → add `roadwarrior.app` and `www.roadwarrior.app`.
- Update DNS: CNAME `www` → `cname.vercel-dns.com`, A `@` → Vercel's IPs.

## 4️⃣ Environment Variable Management

### Where to put what

| Variable type        | Where                                            |
|----------------------|--------------------------------------------------|
| `DATABASE_URL`       | Backend host secrets                             |
| `JWT_SECRET`         | Backend host secrets                             |
| `TWILIO_*`           | Backend host secrets                             |
| `CORS_ORIGINS`       | Backend host env (must include prod frontend URL)|
| `NEXT_PUBLIC_API_URL`| Vercel project env                               |

### Rule of thumb
- **Secrets** (passwords, API keys) → platform secret store, never in git.
- **Public URLs** (frontend API base URL) → safe in `NEXT_PUBLIC_*` (bundled into client).

## 5️⃣ Custom Domain & TLS

- **Vercel** — automatic Let's Encrypt for custom domains.
- **Fly.io** — `fly certs add roadwarrior.app` (also auto-renews).
- **Cloudflare** in front of both — enables DDoS protection and a single DNS panel.

## 6️⃣ CI/CD (basics)

A minimal GitHub Actions workflow (`.github/workflows/ci.yml`):

```yaml
name: CI
on: [push, pull_request]
jobs:
  test-backend:
    runs-on: ubuntu-latest
    services:
      postgres:
        image: postgres:16
        env:
          POSTGRES_PASSWORD: postgres
        ports: ['5432:5432']
        options: >-
          --health-cmd pg_isready
          --health-interval 10s
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-python@v5
        with: { python-version: '3.11' }
      - run: pip install -r backend/requirements-dev.txt
      - run: cd backend && pytest
  lint-frontend:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-node@v4
        with: { node-version: '20' }
      - run: cd frontend && npm ci && npm run lint
```

## 7️⃣ Post-deploy checklist

- [ ] `curl https://api.roadwarrior.app/api/health` → `{"status":"ok"}`
- [ ] Swagger UI loads at `https://api.roadwarrior.app/docs`
- [ ] Frontend loads at `https://roadwarrior.app`
- [ ] CORS: frontend can call backend (check browser devtools → no CORS errors)
- [ ] Neon dashboard shows the first request landing in `riders` (after first survey)
- [ ] SSL Labs grade A or better
- [ ] Logs are being collected (platform default is fine for MVP)
- [ ] Backups are scheduled (or PITR enabled on Neon Pro)
