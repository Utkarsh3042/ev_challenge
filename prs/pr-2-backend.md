# PR #2 — Backend API & Business Logic

## 🎯 Goal
Implement the complete FastAPI backend for **Road Warrior**: all REST endpoints, Pydantic schemas, business logic services (referral, points engine, segments, QR, phone), JWT admin auth, seed data, and a comprehensive test suite. After this PR, the backend can be hit via the FastAPI Swagger UI and the full submission → scoring → leaderboard flow works end-to-end with the database (no frontend, no WhatsApp yet).

## 📋 Scope
- All Pydantic schemas (request/response models)
- All FastAPI routes (public + admin)
- Business logic services (referral, points, segments, QR, phone, i18n)
- JWT authentication for admin
- Sample data seeding
- Unit + integration tests
- API documentation polish

**OUT of scope** (covered elsewhere):
- Frontend (PR #3)
- Real Twilio WhatsApp sending (PR #4) — but the dispatcher interface is defined
- Admin dashboard UI (PR #3)
- Production deployment (PR #5)

## 🧩 Service Layer Specifications

### `services/phone.py`
- `normalize(raw: str) -> str` — strips spaces/dashes, prefixes `+91`, returns E.164
- `validate(raw: str) -> bool` — uses `phonenumbers` library with IN region
- `format_display(e164: str) -> str` — returns `98765 43210` style for UI

**Examples:**
```python
normalize("9876543210")       -> "+919876543210"
normalize("+91 98765 43210")  -> "+919876543210"
normalize("919876543210")     -> "+919876543210"
validate("1234")              -> False
validate("+919876543210")     -> True
```

### `services/referral.py`

**Functions:**
- `generate_unique_code(db) -> str` — generates `RW-XXXX` (uppercase alphanumeric, no 0/O/1/I/l for readability), checks uniqueness in DB, retries up to 5 times
- `find_referrer(db, code: str) -> Rider | None` — looks up by code
- `award_signup_bonus(db, rider) -> None` — adds 10 points, writes to `points_transactions`
- `award_referral_bonus(db, referrer, new_rider) -> tuple[int, list[str]]` — adds 5 points, increments count, checks milestones, returns (new_total, triggered_milestones)
- `check_milestones(db, rider) -> list[str]` — returns list of milestone names newly reached in this call

**Milestone config (in `config.py`):**
```python
MILESTONE_10_REFERRALS = 10
MILESTONE_10_BONUS = 100
MILESTONE_25_REFERRALS = 25
MILESTONE_25_BONUS = 300
MILESTONE_50_REFERRALS = 50
MILESTONE_50_BONUS = 500
```

**Idempotency:** milestones are guarded by boolean flags (`milestone_10_reached`, etc.) so a milestone is only awarded once even if the count is updated multiple times in a race.

### `services/segments.py`

**Function:**
- `compute_segments(answers: dict) -> list[str]` — returns sorted list of segment tags based on the rider's answers

**Segment rules table:**

| Segment | Condition |
|---|---|
| `ev_rider` | `vehicle_type == 'electric'` |
| `petrol_rider` | `vehicle_type in ('petrol', 'diesel')` |
| `diesel_rider` | `vehicle_type == 'diesel'` |
| `swing_rider` | `open_to_switch in ('yes', 'need_info')` |
| `hot_ev_lead` | `vehicle_type in ('petrol','diesel') AND open_to_switch == 'yes'` |
| `insurance_lead` | `has_accident_insurance == 'no' OR has_health_insurance == 'no'` |
| `retrofit_lead` | `vehicle_type in ('petrol','diesel') AND 'retrofit' in interested_in` |
| `rental_lead` | `'ev_rental' in interested_in` |
| `accident_victim` | `paid_out_of_pocket == True` |
| `high_spender` | `weekly_expense >= 1500 OR monthly_maintenance >= 3000` |
| `veteran` | `years_experience >= 3` |

**Test cases** in `test_segments.py` cover every segment + the empty case.

### `services/qr_service.py`
- `generate_qr_png(data: str, size: int = 200) -> bytes` — returns PNG bytes using `qrcode` library
- The `data` param is the full share URL: `f"{APP_URL}/form?ref={code}"`

### `services/whatsapp_dispatcher.py` (interface, mock impl here)
Defines an abstract interface so PR #4 can drop in Twilio without changing call sites:

```python
class WhatsAppDispatcher(Protocol):
    async def send_welcome(self, rider: Rider) -> MessageResult: ...
    async def send_milestone(self, rider: Rider, milestone: str) -> MessageResult: ...
    async def send_my_score(self, rider: Rider, stats: ScoreStats) -> MessageResult: ...
    async def send_referral_share(self, rider: Rider) -> MessageResult: ...
```

**In this PR:** a `MockWhatsAppDispatcher` that:
- Formats the message body using the rider's language from `locales/`
- Logs to console `[WHATSAPP MOCK] To: +91xxx | Template: welcome_hi | Body: ...`
- Inserts a row in `whatsapp_messages` with `status='sent'`
- Returns a `MessageResult(success=True, sid='MOCK-uuid')`

PR #4 swaps this with `TwilioWhatsAppDispatcher` via a config flag.

  - Sum of all points awarded
  - Active referrers count (where `referral_count > 0`)

### `services/i18n.py`
- `load_locale(lang: str) -> dict` — reads `locales/{lang}.json` and returns parsed dict
- `get_message(lang: str, key: str, **vars) -> str` — loads locale, navigates dotted key, applies `.format(**vars)`
- Caches loaded locales in module-level dict (file mtime invalidated on reload)

### `auth/jwt.py`
- `create_access_token(subject: str, expires_delta: timedelta | None = None) -> str` — HS256 JWT
- `decode_token(token: str) -> dict` — verifies signature, returns claims or raises 401

### `auth/security.py`
- `hash_password(plain: str) -> str` — bcrypt via passlib
- `verify_password(plain: str, hashed: str) -> bool`

## 🔄 Submit Flow (End-to-End Logic)

```
POST /api/riders/submit receives RiderSubmit
  ↓
1. Normalize & validate phone (services/phone.py)
  ↓
2. Check if phone already exists in DB
   YES → fetch existing rider, mark is_duplicate in response, do NOT create new row
         send a "you already registered" WhatsApp with their existing code
         return 200 with is_duplicate=true
   NO  ↓
3. If referred_by_code present:
     - Look up referrer
     - If found → store referred_by_code, prepare to award them later
     - If not found → ignore the code, log warning, proceed as if no referral
  ↓
4. Generate unique referral code for new rider (services/referral.py)
  ↓
5. Compute segments (services/segments.py)
  ↓
6. INSERT rider row with points=10
  ↓
7. Write points_transactions row (type=signup_bonus, delta=+10)
  ↓
8. Dispatch welcome WhatsApp (mock in this PR)
  ↓
9. If referrer exists:
     - In a single transaction:
       - UPDATE referrer SET points = points + 5, referral_count = referral_count + 1
       - INSERT points_transactions row (type=referral_bonus, delta=+5, related_rider_id=new)
     - Check milestones (10/25/50)
     - If milestone reached:
       - UPDATE rider SET points = points + bonus, milestone_X_reached = TRUE
       - INSERT points_transactions row (type=milestone_X, delta=+bonus)
       - Dispatch milestone WhatsApp
  ↓
10. Return RiderSubmitResponse with full preview
```

**Transaction safety:** Steps 6+7+9 run in DB transactions. If any step fails, the whole submit rolls back (no orphan points, no orphan rider).

## 🛡️ Error Handling
All routes use a global exception handler that returns:
```json
{
  "error": {
    "code": "VALIDATION_ERROR",
    "message": "Phone number is invalid",
    "field": "phone"
  }
}
```

Error codes used:
- `VALIDATION_ERROR` (422)
- `NOT_FOUND` (404)
- `UNAUTHORIZED` (401)
- `FORBIDDEN` (403)
- `RATE_LIMITED` (429)
- `INTERNAL_ERROR` (500)
- `PHONE_DUPLICATE` (200, but `is_duplicate=true` in body)

## 🌱 Seed Data (`utils/seed.py`)

Idempotent script that:
1. Creates 1 admin: `admin@roadwarrior.in` / `admin123` (only if no admin exists)
2. Creates 25 sample riders:
   - 5 petrol riders in Bangalore (Swiggy/Zomato)
   - 3 EV riders in Bangalore (Blinkit)
   - 3 diesel riders in Delhi (Porter)
   - 4 petrol riders in Mumbai (Dunzo)
   - 2 EV riders in Hyderabad
   - 4 petrol riders in Chennai
   - 4 in "Other" cities
3. Creates 2 referral chains:
   - Rider A (RW-1001) refers 12 others → triggers milestone 10
   - Rider B (RW-2002) refers 30 others → triggers milestone 25
4. Mixes languages (10 EN, 10 HI, 5 KN)
5. Mixes segments so dashboard has variety
6. Skips if data already exists (re-runnable)

Run via: `python -m app.utils.seed` or `make seed`

## ⚠️ Risks & Notes
- **Test DB:** must use a separate Neon database (`roadwarrior_test`) to avoid wiping production data. Document in SETUP.md.
- **Race conditions** on referral code generation: very unlikely (4 chars from a 32-char alphabet = 1M combos) but handled with retry.
- **Mock dispatcher** must be wired in `main.py` via dependency injection, not imported directly, so PR #4 can swap cleanly.
- **JWT secret** in `.env.example` is `change-me` — must be rejected at startup if not set in production.
- **CSV export** must handle commas/quotes in free-text fields (vehicle_brand_model, etc.) — using Python's `csv` module.
- **Rate limiting** on `/api/riders/submit` to prevent abuse — using `slowapi` (10 req/min per IP).
